# Database Schema

We are using **Supabase PostgreSQL** for robust storage. For local development/demo purposes, an in-memory fallback is provided if Supabase credentials are not configured.

## Tables

### 1. `users`
Police officer authentication.
- `id` (UUID, PK)
- `username` (VARCHAR)
- `password_hash` (VARCHAR)
- `role` (VARCHAR)
- `full_name` (VARCHAR)
- `badge_number` (VARCHAR)

### 2. `edge_nodes`
Registry of distributed processing nodes.
- `id` (VARCHAR, PK)
- `name` (VARCHAR)
- `status` (VARCHAR: online, offline, degraded)
- `location_name` (VARCHAR)
- `latitude`, `longitude`
- Performance stats: `cpu_usage`, `gpu_usage`, `fps`
- Analytics: `metadata_sent_bytes`, `raw_video_sent_bytes`

### 3. `cameras`
Registry of cameras attached to edge nodes.
- `id` (VARCHAR, PK)
- `edge_node_id` (FK to edge_nodes)
- `name`, `location_name`
- `latitude`, `longitude`
- `status`, `fps`

### 4. `queries`
Vehicle search queries initiated from the dashboard.
- `id` (UUID, PK)
- `user_id` (FK to users)
- Search params: `plate`, `vehicle_color`, `vehicle_type`
- `status` (pending, processing, complete)
- `result_count` (INT)

### 5. `detections`
Matches reported by edge nodes.
- `id` (UUID, PK)
- `query_id` (FK to queries)
- `camera_id` (FK to cameras)
- `edge_node_id` (FK to edge_nodes)
- Match details: `plate`, `vehicle_type`, `vehicle_color`, `confidence`
- Location details: `latitude`, `longitude`, `timestamp`
- Bandwidth metrics: `metadata_size_bytes`, `raw_video_bytes` (always 0)

### 6. `trajectories`
Reconstructed paths generated by the coordinator.
- `id` (UUID, PK)
- `query_id` (FK to queries)
- `vehicle_plate` (VARCHAR)
- `points` (JSON: array of ordered detections with calculated distance/speed)
- `total_detections`, `first_seen`, `last_seen`
- `status` (VARCHAR)

### 7. `system_logs`
Audit and debug logs.
- `id`, `level`, `source`, `message`, `metadata`, `timestamp`
